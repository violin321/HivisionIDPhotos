# Phase 4 Web v2 deployment prep

Target external host: `https://idphoto-ai.violinai.qzz.io`.

Do **not** point this stack at `idphoto.violinai.qzz.io`; that hostname is reserved for the existing Gradio site.

## Services

- FastAPI adapter: `deploy_api:app`
  - default local port: `8000`
  - health: `GET /api/health`
  - static generated files: `/runtime/uploads/*`, `/runtime/results/*`
- Web v2: `web/` Next.js app
  - default local port: `3000`
  - API base configured by `NEXT_PUBLIC_API_BASE_URL`

## Local smoke

```bash
.venv/bin/python -m py_compile deploy_api.py
.venv/bin/python -m uvicorn deploy_api:app --host 127.0.0.1 --port 8000
API_BASE_URL=http://127.0.0.1:8000 .venv/bin/python scripts/e2e_phase4_api.py

cd web
NEXT_PUBLIC_API_BASE_URL=http://127.0.0.1:8000 npm run build
NEXT_PUBLIC_API_BASE_URL=http://127.0.0.1:8000 npm run dev -- --port 3000
```

One-command local API check:

```bash
./scripts/run_phase4_local.sh
```

## Production environment

Suggested values for the target deployment:

```bash
API_HOST=127.0.0.1
API_PORT=8000
WEB_PORT=3000
NEXT_PUBLIC_API_BASE_URL=https://idphoto-ai.violinai.qzz.io
```

If a reverse proxy serves both apps under the same origin, route:

- `/api/*` -> FastAPI `127.0.0.1:8000`
- `/runtime/*` -> FastAPI `127.0.0.1:8000`
- everything else -> Next.js `127.0.0.1:3000`

## Boundaries

- `officialResult` is generated by deterministic Hivision/IDCreator only.

- No GPT-image-2 call, OpenAI key, provider Bearer token, or hard-coded local API tunnel is required.

## idphoto-ai production deploy script

Use the checked-in deploy script from the repository root, or from any current working directory:

```bash
./scripts/deploy_idphoto_ai.sh
```

What it does:

1. Compiles `deploy_api.py` and safe static-check scripts under `scripts/` (it skips `e2e_*.py`, `test-*.py`, model download, and packaging helpers).
2. Runs `npm run build` in `web/`.
3. Runs `scripts/prepare_next_standalone_static.sh` so `web/.next/static` is copied into `web/.next/standalone/.next/static` for Next `output: 'standalone'`.
4. Restarts only the PM2 processes `idphoto-ai-api` and `idphoto-ai-web`.
5. Waits for local `GET http://127.0.0.1:18084/api/health`, the local web home page, and one local `/_next/static/...` chunk to return HTTP 200.
6. Performs best-effort external checks against `https://idphoto-ai.violinai.qzz.io` using a browser-like User-Agent. These are non-fatal by default because Cloudflare may return 1010 to non-browser clients.

Safe validation without restarting live services:

```bash
./scripts/deploy_idphoto_ai.sh --check
```

Useful options:

- `--skip-external`: skip external URL checks.
- `--strict-external`: make external health/static checks fatal.
- `--deploy-api-only`: compile only `deploy_api.py` instead of also compiling safe helper scripts.

### PM2 env preservation warning

Do **not** deploy with:

```bash
pm2 restart ecosystem.idphoto-ai.config.cjs --update-env
```

That can replace the existing PM2 process environment with the current shell environment and clear auth/session values such as `IDPHOTO_APP_USERNAME`, `IDPHOTO_APP_PASSWORD`, and `IDPHOTO_APP_SESSION_SECRET` if the shell does not have them set.

The deploy script intentionally restarts by process name only:

```bash
pm2 restart idphoto-ai-api
pm2 restart idphoto-ai-web
```

This preserves the current PM2 auth/session environment while picking up rebuilt code and standalone assets.
